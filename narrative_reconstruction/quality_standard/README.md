# Единый стандарт качества повествования «Дикое Поле»

Это нормативная точка входа для любой работы с игровыми текстами: анализа, художественной редакции, исправления ошибок, интеграции нового контента и приёмки.

## Фундаментальное правило

Каждый текст — часть единого взаимосвязанного мира. Ни один файл, квест, диалог или пакет не проверяется изолированно. Каждое изменение оценивается по последствиям для всех связанных материалов. Каждый новый материал проверяется на совместимость с уже утверждённым миром. Результат принимается только после независимой проверки и регрессионного контроля.

## Как применять

1. Перед любой задачей прочитать 00_MASTER_STANDARD.md.
2. При выявлении проблем использовать 01_DEFECT_TAXONOMY.md и шаблон finding.
3. Для связей и канона применять 02_WORLD_CONTINUITY_MODEL.md.
4. Для заданий и игровых ветвей применять 03_QUEST_PLAYABILITY_STANDARD.md.
5. При исправлении и проверке применять 04_IMPLEMENTATION_AND_VALIDATION.md.
6. При добавлении нового контента дополнительно применять 05_NEW_CONTENT_INTEGRATION.md.
7. В отчёте использовать соответствующие шаблоны.

## Область действия

Стандарт обязателен для всех существующих и будущих пакетов, квестов, сцен, диалогов, персонажей, предметов, локаций и сюжетных линий проекта.

Он применяется совместно с действующими промптами в narrative_reconstruction/prompts/. Каждый такой промпт должен явно ссылаться на стандарт. Стандарт определяет обязательный процесс качества, но не заменяет утверждённый канон, решения владельца и конкретные ограничения отдельной задачи.

## Источники проекта

Перед работой агент обязан найти фактические актуальные версии:
- игровые тексты в revised/;
- канонические документы в canon/;
- change_log/;
- утверждённые решения владельца;
- предыдущие аудиты, интеграционные отчёты и реестры зависимостей в reports/.

Не считать приведённые здесь примеры путей исчерпывающим перечнем. Проверять фактическую структуру репозитория.

Для решений от 2026-11-27 использовать зафиксированный журнал narrative_reconstruction/reports/owner_recommendations_p01_p36/12_OWNER_APPROVALS_LOG.md и связанные документы рекомендаций. Журнал подтверждает утверждение 32 решений, но сам по себе не означает, что эти решения уже реализованы в игровых текстах. Для реализации требуется отдельная задача с соответствующим объёмом разрешений.

## Неприкосновенные границы

- Не создавать второй параллельный канон или дублирующий реестр вместо действующего.
- Не превращать гипотезы и предложения агента в утверждённые факты.
- Не менять канон, механики, технические ID и решения владельца без необходимого основания и полномочий.
- Не рассчитывать баланс, экономику, XP, валюту, репутацию, карму, ресурсы и числовую прогрессию.
- Не тестировать TTS, голосовые движки и воспроизведение звука.
- Не вводить требования к дополнительным аудио-, тактильным, обонятельным или навигационным подсказкам.
- Не переписывать хороший художественный текст ради единообразия.
- Не считать локально проверенный файл полностью принятым без проверки его связей и регрессии.
