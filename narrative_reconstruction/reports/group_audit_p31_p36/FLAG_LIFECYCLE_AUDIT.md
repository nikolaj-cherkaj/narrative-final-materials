## 2. DONE / повтор / відмова

- Кожен DONE ставиться лише після завершення відповідного фіналу/відлуння.
- Провал (Fail & Retry Loop) і відмова (Варіант 4/5) DONE не ставлять; це перевірено в кожному квесті.
- Повторний вхід при активному DONE — лише пам’ять; повторні нагороди не видаються.
- `FLAG_NALIVAYKO_LAST_STAND` — термінальний; окремого DONE немає, повтору немає; P01 D-015 не має корчменної реакції.
- `FLAG_P31_Q01_DONE`/`Q02`/`Q03`/`Q04`/`Q05` — один DONE на квест, будь-який фінал.
- `FLAG_P32_Q03_DONE` може ставитися фіналом А/Б або відлунням; відлуння після Б дає `TRAP`+`GROVE`.
- `FLAG_P33_Q03_DONE` може ставитися фіналом А/Б або відлунням; відлуння після Б дає `HUT`+`BLESSING`.

## 4. Проблемні життєві цикли

### 4.1. `FLAG_P33_Q04_DONE` — `GA-P33-001`

- Картка: «титана знешкоджено (будь-який фінал)» (`FLAG_REGISTRY.md:3459`).
- Фактично: фінал Б (`P33:462–470`) не знешкоджує Арідника; він лише дає плащ.
- Наслідок: DONE і `WINGS` можуть існувати при живому Аріднику; повторна репліка «полонина дихає вільно» суперечить стану.
- **Рекомендація:** додати наслідок для Арідника у фінал Б або змінити картку DONE.

### 4.2. `FLAG_P34_Q03_SEALED`/`BRONZE` — `GA-P34-001`

- Флаги коректно взаємовиключні, але Акт II (`P34:306`) зобов’язує взяти Пектораль, а ці фінали її лишають.
- **Рекомендація:** точка вибору після Грифона; інакше флаги описують недосяжний/суперечливий стан.

### 4.3. `FLAG_P31_Q01_SPOKUTA`/`LITOPYS` — `GA-P31-001`

- `SPOKUTA` може ставитися без `LITOPYS`, навіть якщо хата не врятована; `P31:80` веде до `LITOPYS` при пожежі.
- **Рекомендація:** зробити B залежним від вуженя; якщо B має бути пост-пожежним, це варіант В із `LITOPYS` **замість** `SPOKUTA` (флаги взаємовиключні).

### 4.4. Документаційні нюанси

- `FLAG_P34_Q02_DONE` має назву «Бабу замирено», хоча фінал Б її розбиває; ID і SET/CHECK коректні, назва — умовна.
- `FLAG_P31_Q03_WEDDING` — калька в реєстрі (`GA-P31-005`).
- `FLAG_P32_Q01_DONE` — фінал А дає щит, Б/В не описують його долю; OBS `OBS-P32-SHIELD-BC`.

## 5. Висновок

- 78/78 ID мають повний цикл; дублікатів і CHECK без SET немає.
- 75 ID не мають зауважень до життєвого циклу; 3 лінії потребують узгодження: P31 Q01, P33 Q04, P34 Q03.
- Після виправлення цих трьох ліній флаговий аудит може бути `GO`.
