## 6. `FLAG_P20_DAILY02_LIFELINE` — детальная проверка варианта B

**Текст:**
- P20:219: «одноразово рятує від смертельного удару… одночасно діє не більше одного заряду: новий знак замінює попередній і не накопичується».
- P20:222: «Після спрацювання порятунку знак гасне й оновлюється лише наступним успішним фіналом Б».
- P20:223: SET `DAILY02_DONE` + `DAILY02_LIFELINE` (пам'ять знака, постійна; заряд — не більше одного, без накопичення).
- Реестр §20: тип state (память знака; заряд одноразовый, без накопления); CLEAR — постоянный, «витрачений заряд оновлюється лише наступним успішним фіналом Б».
- Carryover §2.7/§3.1, changelog — та же семантика.

**Симуляция:**

| День | Действие | `DAILY02_DONE` | `LIFELINE` (память) | Заряд | Результат |
|---|---|---|---|---|---|
| 1 | Финал Б | SET | SET | 1 | Один заряд |
| 1 | Смертельный удар | — | SET | 0 | Заряд сработал, знак погас |
| 1 | Повтор Б | DONE активен | SET | 0 | Блокировано, нового заряда нет |
| 2 | 06:00 | CLEAR | SET | 0 | Квест снова доступен |
| 2 | Финал Б | SET | SET | 1 | Новый заряд (замена, не +1) |
| 2 | Финал А | SET | SET | 1 | Заряд не тронут (А не даёт и не снимает) |
| 3 | Без Б | CLEAR | SET | 1 | Заряд сохраняется до использования/нового Б |
| 3 | Смертельный удар | — | SET | 0 | Сработал |
| 4 | Финал Б | SET | SET | 1 | Восстановлен только следующим Б |

**Вывод:** семантика варианта B выполнена; накопления нет; повтор в тот же день ограничен DONE; новый успешный Б заменяет предыдущий знак; после срабатывания заряд восстанавливается только следующим Б. **`VERIFIED FIXED`.**

**Остаточная реализационная заметка:** `LIFELINE` — это память/разблокировка, а заряд — отдельная runtime-переменная. Владелец принял «новый флаг траты не нужен»; в материалах нет имени этой переменной. Это OBS `GA-P20-016`, не текстовый дефект.

## 7. Сводка жизненных циклов

### SET без CHECK
- P16–P19: нет; каждый state-флаг читается в блоке финала/памяти.
- P20: `DAILY01_CAPTIVE`, `WEEKLY02_HELMSMAN`, `SMITH_MASTER`, `COURIER_GOLD` — SET/CHECK в одной строке, отдельного сценария нет; это OBS, не потеря состояния.
- P20 daily/weekly финалы A/B не имеют state-флагов; `DONE` не различает финал — это корень `GA-P20-012`…`015`.

### CHECK без SET
- Не найдено. Все проверяемые флаги имеют SET в тексте или во внешнем пакете (P01 для `TALES19_*`; P24 для `ASHES` — наоборот, CHECK отсутствует).

### Временные флаги без CLEAR
- Не найдено: P20 daily/weekly DONE имеют CLEAR по времени; P16–P19 DONE — one-shot.

### CLEAR, стирающие постоянное состояние
- Не найдено: P20 CLEAR применяется только к periodic DONE; `TAMED`, `STREAK_7`, `CAPTIVE`, `LIFELINE`, `HELMSMAN`, `SMITH_MASTER`, `COURIER_GOLD` не снимаются.

### Несколько флагов на одно состояние
- P20 daily: `DAILY01_DONE` (periodic) + `CAPTIVE` (memory) — разные роли.
- P20 daily 03: `DAILY03_DONE` (periodic) + `STREAK_7` (one-shot) — разные роли.
- P20 weekly 01: `WEEKLY01_DONE` (periodic) + `TAMED` (permanent lock) — разные роли; `TAMED` доминирует.
- P16–P19: DONE + один state — нормальная схема «маркер + память финала».

### Невозможные/недостижимые состояния
- `P16_Q03_WARDENS`, `P16_Q02_FOREST`, `P19_Q03_GUARDIAN` — достижимы и сетаплены (проверено).
- `P20_DAILY01` финал В — недостижим (`GA-P20-012`).
- `P20_DAILY02` A/B/C — достижимы, но не взаимоисключающие (`GA-P20-013`).
- `P20_WEEKLY02` B — не сетаплен (`GA-P20-015`).

### Циклы повторной награды
- P16–P19: DONE блокирует повтор; циклов нет.
- P20 daily/weekly: повторные награды by design (periodic); исключение — D2/D3/W2, где несколько финалов могут дать несколько наборов за один запуск (`GA-P20-013`…`015`).
- P20 radiant: повторные выплаты by design; `SMITH_MASTER`/`COURIER_GOLD` one-shot.
