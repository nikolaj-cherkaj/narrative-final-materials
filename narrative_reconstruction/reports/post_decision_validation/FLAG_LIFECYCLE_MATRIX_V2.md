## 3. Новый флаг и правила регистрации

### 3.1. `FLAG_P05_CHUHAYSTER_ABSENT`

- **Причина:** текущий `FLAG_P05_CHUHAYSTER_KILLED` смешивал два значения: «игрок убивал Чугайстера» и «Чугайстер сейчас отсутствует после респауна».
- **Решение:** `_KILLED` — постоянная историческая память; `_ABSENT` — временное состояние на три рассвета. Респаун снимает только `_ABSENT`.
- **Регистрация:** этот отчёт, `POST_DECISION_CHANGELOG.md`, `canon/CHARACTERS.md` (NPC-0137), `change_log/CHANGELOG_2026-11-24_OWNER_DECISIONS.md` §9.
- **Статус:** технический ID, требует подтверждения владельца перед FOUNDATION FREEZE.

### 3.2. Правила для будущих флагов

1. Новый ID не вводится, если можно переиспользовать существующий без смешения значений.
2. Если нужны два состояния — разделять их, а не перегружать один флаг.
3. Каждый новый ID фиксируется в этом реестре или его следующей версии.
4. У каждого флага должен быть минимум один содержательный CHECK-потребитель.
5. CLEAR описывается явно; «само сбросится» — не описание.
